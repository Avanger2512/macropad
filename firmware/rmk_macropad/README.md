# ESP32-S3 Macropad — RMK / Vial

Claude Code and Codex question/permission alerts are now supported through a separate
vendor USB HID interface, with source logos, a temporary OLED overlay and breathing LEDs.
See [host bridge setup and recovery](../host/README.md). The device receives only
notification state; hooks do not approve actions or answer questions.

Built and flashed on October 20, 2026. macOS enumerated **Macropad Vial**
(VID `FEED`, PID `6061`) with keyboard, consumer-control and Vial raw-HID interfaces.
The owner confirmed Vial discovery, OLED and LEDs. A layer-0 Ghostty shortcut
was subsequently configured in Vial and verified (Ctrl+Option+Command+G).

## Build

Install Rust, Espressif `espup`, its ESP32-S3 toolchain, and `espflash` from their
official distributions. Load the export script generated by espup in each shell.
The successful local build used espup 0.18.0, ESP Rust 1.97.0.0 and espflash 4.6.0.
RMK is pinned by git revision in Cargo.toml; keep Cargo.lock.

```sh
cd firmware/rmk_macropad
. "$HOME/export-esp.sh"
cargo +esp build --release --locked
espflash flash --port /dev/cu.usbmodem2101 --chip esp32s3 \
  --before usb-reset --after hard-reset --flash-size 4mb \
  --flash-mode dio --flash-freq 80mhz --partition-table partitions.csv \
  target/xtensa-esp32s3-none-elf/release/macropad-vial
```

Adjust the port and target directory to the current machine. The actual build
used isolated Cargo/Rustup homes under `/tmp/macropad-rust` and
`CARGO_TARGET_DIR=/tmp/macropad-rmk-target`; these temporary tools may disappear.
Always use the checked-in partition table: the final 64 KiB is RMK settings
storage, not application space. The first application image was 614,800 bytes.
The partition subtype `spiffs` only labels the reserved region; RMK manages its
contents directly and does not mount a SPIFFS filesystem.

When RMK owns native USB, the old serial port may disappear. For subsequent
flashes, hold BOOT, tap RESET, release BOOT and select the ROM USB serial port.
See [USB recovery](../FLASHING.md) if the ROM loader does not respond.

## Controls and customization

- SW1–SW6: GPIO1,2,3,6,5,4; encoder press: GPIO10, all active low.
- Encoder A/B: GPIO8/9, four transitions per detent, reversed direction.
- Base keys: F13–F18; encoder: volume up/down; press: mute.
- Four editable layers. Extra layers initially inherit Base assignments.
- Vial physical unlock combination: hold SW1 and SW6 when prompted.
- OLED: SH1106 128x64, SDA11/SCL12, address 0x3C, custom interactive status renderer (see below).
- Four WS2812 on GPIO13: dim green/blue/orange/purple for layers 0/1/2/3.
  This is local layer indication; VialRGB controls are not implemented.

In Vial assign a key to `MO(1)` or `TG(1)` to reach another layer. Changes are
stored by RMK. Export a Vial layout file to back up your assignments.
OLED content is configured in firmware, not in the Vial GUI.

## Validation and rollback

```sh
python3 -m unittest discover -s firmware/tests -p 'test_rmk_config.py'
rustc --test firmware/rmk_macropad/src/rgb_policy.rs -o /tmp/macropad-rgb-tests
/tmp/macropad-rgb-tests
```

Run these commands from the repository root using a host Rust compiler.
The config checks and two RGB encoding tests passed before flashing.
The release compiler emitted an ESP linker RWX-segment warning; linking and
image validation completed successfully.

A complete pre-migration 4 MiB backup and checksum are saved locally in
`build/recovery/arduino-working-2026-10-20.bin` and `.bin.sha256` (git ignored).
To restore it, enter the ROM loader, verify its SHA-256 and use esptool:

```sh
python -m esptool --chip esp32s3 --port PORT --before usb-reset \
  --after hard-reset write-flash 0x0 build/recovery/arduino-working-2026-10-20.bin
```

This replaces all flash contents, including saved Vial assignments. Keep the
backup outside temporary directories if long-term recovery is required.
The original Arduino hardware-test sources remain in `../macropad_test/`.

## Interactive OLED update — October 20, 2026

The display uses RMK's existing renderer interface and existing key-event latch:

- Current layer and local profile label: BASE / WORK / CAD / MEDIA.
- Robot eyes blink briefly every four seconds while idle.
- Key presses and encoder turns enlarge the eyes and show INPUT for 400 ms.
- The bottom activity bar lights during input; idle status reads READY.
- Sleep clears the screen. Refresh is limited to 10 frames per second.

The display reports local input activity, not which application is focused or
whether Ghostty opened. Profile labels are firmware presets, not editable names
read from Vial. The event latch may combine several very fast inputs into one
reaction; it is not an input counter.

Safety: the RMK git revision, feature list, matrix, layers, GPIOs, UID, storage
address and framing sizes were retained. RMK's generated schema inputs were
compared before/after because changing them can reset dynamic settings. The
OLED-only update writes the application at `0x10000`; it does not rewrite the
bootloader, partition table or settings partition.

Before updating, current Vial assignments were exported to
`../backup/denis_macropad_before_display_2026-10-20.vil`. A complete working RMK
flash backup is in `build/recovery/rmk-before-display-2026-10-20.bin` at the
repository root, with its SHA-256 beside it. `build/rmk/macropad-vial-before-display.elf`
is the preceding executable. These binary recovery files are git ignored.

Animation timing tests (from repository root, host Rust compiler):

```sh
rustc --edition 2024 --test firmware/tests/test_display_policy.rs -o /tmp/macropad-display-tests
/tmp/macropad-display-tests
```

Reference: [RMK display renderer documentation](https://rmk.rs/main/docs/features/display).

Hardware update result: esptool verified the application checksum and macOS
re-enumerated Macropad Vial. After the initial RTS reset the board remained in
ROM mode; `esptool --chip esp32s3 --port PORT --before usb-reset --after watchdog-reset chip-id`
returned it to the application successfully. Vial's full exported JSON before
and after updating matched exactly (keys, encoder map, macros and settings),
including layer-0 `LCAG(KC_G)` for Ghostty. Physical animation appearance still
needs owner confirmation.

## Saved everyday Vial assignments

Load `../backup/denis_macropad_current_2026-10-20.vil` using Vial's File → Load
saved layout to restore the latest exported settings. This snapshot includes
layer switching on the encoder and these layer-0 buttons:

- SW1: Ctrl+Option+Command+G, handled by the Mac shortcut “Ghostty — показать”.
- SW2: Ctrl+Shift+Tab (previous tab in Ghostty).
- SW3: Ctrl+Tab (next tab in Ghostty).

The macOS shortcut itself is not part of the keyboard backup: create it in
Shortcuts with Open App → Ghostty and assign the same Ctrl+Option+Command+G.
Other apps can process these ordinary key combinations differently.

Vial edits are stored immediately and do not require flashing. When replacing a
compound action through Any, select its upper/whole-action area first. Selecting
the lower Tab area edits only the nested key and retains existing modifiers.
Firmware defaults in keyboard.toml remain F13–F18/volume; saved runtime settings
and exported .vil files are the customized configuration.
